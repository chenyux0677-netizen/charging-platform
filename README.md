# 东软电动汽车充电桩应用管理平台

一个 Qt6/C++ 编写的**充电桩应用管理演示项目**,由三部分组成:

- **用户端**:选电站 → 选充电桩 → 充电 → 订单 / 余额(手机风格界面)
- **管理员端**:销售统计、充电桩状态、充电站 / 桩管理、用户管理(桌面风格界面)
- **数据库中间层**:内嵌 SQLite + TCP 服务,负责存取数据并向所有在线端广播变化

> 这是**演示项目**(毕设 / 课设向):充电为软件模拟(**1 秒 = 1 分钟**),无真实硬件;
> 服务器与数据库随管理员端进程启动,可**同机开多进程演示**,也可**多台真机联机**(见下文)。

## 架构

```
┌────────────┐        TCP+JSON ┌──────────────────────────────┐
│  用户端     │ ──────────────► │ 管理员端(内含服务器 + SQLite) │
│ RemoteDS   │   广播 dataChanged │  Server + LocalDataSource  │
└────────────┘ ──────────────── └──────────────────────────────┘
```

- 两端界面只依赖抽象接口 `DataSource`(`query / insertRow / updateRows / removeRows` + `dataChanged` 信号)
- 用户端用 `RemoteDataSource`(走网络),服务器用 `LocalDataSource`(本地 SQLite)——对界面完全无感
- 任何一端写入 → 服务器广播 `dataChanged` → 另一端**实时刷新**(延迟到事件循环空闲再触发,防"请求套请求")
- 表结构集中在 `core/TableDef.cpp`,加表 / 加列只改这一处

## 目录结构

```
core/        数据层(DataSource 接口 / 本地与网络实现 / 表定义)
server/      数据库中间层(收请求、回响应、广播变化)
common/      两端共用(角色选择页 / 全局上下文 / 协议)
user/        用户端      admin/      管理员端
resources/   QSS 样式(common.qss + user.qss / admin.qss)
tests/       自检程序(db_selftest / net_selftest / gui_flow_test)
```

## 已实现功能

### 用户端

- 手机号登录,首次输入**自动注册**(昵称 = "用户" + 后四位);冻结账号登录会被拦
- 电站列表(单价 / 空闲桩数)→ 电站详情按类型功率筛选桩 → 选桩模拟充电(实时显示时长 / 电量 / 费用)
- **开始充电由服务器单事务完成**:同一用户、同一电桩同一时刻只能有一笔"充电中"订单,并发抢桩不冲突
- **结束充电由服务器按"开始→当前"结算**(时长 × 功率 = 电量,电量 × 单价 = 金额);**余额不足时整单不通过**,订单保持"充电中",余额不会被扣成负数
- 订单页:历史订单明细;"充电中"订单可**重新结算**(充值后再结即可)
- 我的:个人信息与余额,**充值走服务器接口**(冻结账号无法充值)

### 管理员端

- 默认账号 `admin` / `123456`(首次启动自动创建)
- **销售统计**:已完成订单数 / 总营收 / 总充电量 / 平均每单汇总卡;**各充电站营收柱状图 + 订单量占比饼图**(图例显示站名);范围可切全部 / 今日 / 近 7 天 / 近 30 天,订单变化自动刷新
- **充电桩状态**:全站电桩实时状态一览(只读),可按状态筛选、手动刷新;**充电中的桩逐秒实时显示充电用户 / 本次已充时长 / 电量 / 费用**(充电进度由用户端心跳周期上报、服务端统一折算后广播)
- **充电桩管理**:增 / 改 / 删,可按电站筛选;删除走服务端安全接口,**正在使用或已有订单记录的桩会拒绝删除**
- **充电站管理**:增 / 改 / 删,删除会连带删除其下所有桩,但**站内任一桩正在使用或已有订单记录时整站拒绝删除**
- **用户管理**:列表(状态筛选 / 余额 / 注册时间),**封号(冻结)/ 解封**,与用户端登录拦截闭环

### 数据层与通信

- SQLite 本地存储(`app.db` 自动建表,首启写入种子数据:3 个电站、16 根桩)
- **旧库自动迁移**:启动时按表定义比对缺失列自动 `ALTER TABLE` 补上,旧版本遗留的 `app.db` 无需删除即可升级
- **表级约束 + 部分唯一索引**:CHECK / 外键(RESTRICT)/ 同一用户、同一电桩同一时刻只一笔"充电中"(约束与索引对**新建库**生效)
- **服务端业务单事务**:占桩开单 / 结算 / 充值封装成 `DataSource` 业务接口,单事务执行(结算幂等、余额不足整单回滚),杜绝客户端多步直写造成的并发抢桩与扣成负数
- **崩溃自愈**:服务器启动时按"充电中"订单恢复电桩状态(有订单的桩回"使用中",异常遗留的"使用中"释放回"空闲")
- TCP 监听 `0.0.0.0:9527`,局域网内多台设备可连同一份数据

### 界面与皮肤

- 按所选角色加载样式:`common.qss`(公共基底)+ `user.qss`(用户端手机风格)/ `admin.qss`(管理员端桌面风格)

## 编译与运行

### 依赖(Linux / Ubuntu 22.04)

| 软件 | 安装命令 |
|---|---|
| g++ / CMake ≥ 3.5 | `sudo apt install g++ cmake` |
| Qt 6 开发库 + SQLite 驱动 | `sudo apt install qt6-base-dev qt6-base-dev-tools libqt6sql6-sqlite` |
| **libqt6charts6-dev**(销售统计图表,**必需**) | `sudo apt install libqt6charts6-dev` |
| (可选) Qt Creator | `sudo apt install qtcreator` |

### 编译

```bash
cmake -S . -B build
cmake --build build -j4     # 2 核机器建议 -j2
```

产物(在 `build/`):`charging-platform` 主程序 / `gui_flow_test` / `net_selftest` / `db_selftest`。

### 运行演示(两个程序实例 = 模拟两台设备)

1. `./charging-platform` → 选**管理员端**,登录 `admin`/`123456`。该进程同时是服务器:创建 `app.db`、监听 `0.0.0.0:9527`,**保持运行不要关**。
2. 再运行一次 `./charging-platform` → 选**用户端**,服务器地址保持 `127.0.0.1:9527`,输任意 **11 位手机号**登录(首次自动注册)。

用户端的一切操作会实时同步到管理员端。想单机体验联机效果,把上面"两台设备"换成同一台电脑的两个窗口即可。

### 多设备联机(两台真机)

**谁跑管理员端,谁就是数据源。** 在管理员那台机器上放行 9527 端口、查出局域网 IP(Windows `ipconfig` / Linux `ip addr`),用户端把角色选择页里的服务器地址改成该 IP 即可,无需改代码。同一局域网内只跑**一个**管理员端(多开 = 各自独立的数据库)。

## 常见问题(FAQ)

| 现象 | 原因 | 解决 |
|---|---|---|
| 用户端提示"连接服务器失败" | 管理员端(服务器)没启动 | 先启动管理员端并保持运行 |
| 管理员端提示"启动失败" | 端口 9527 被占用 | 关闭占用 9527 的进程 |
| 报错 "QSQLITE driver not loaded" | 缺 SQLite 驱动包 | `sudo apt install libqt6sql6-sqlite` |
| CMake 配置报错找不到 Qt6 Charts | 缺图表库 | `sudo apt install libqt6charts6-dev` |
| 登录提示"账号已冻结" | 被管理员封号 | 管理员端「用户管理」页点「解封」 |
| 结束充电提示结算失败、订单停在"充电中" | 余额不足(防扣负) | 到「我的」页充值,再到订单页重新结算 |
| 删除桩 / 站被拒绝 | 桩使用中或已有订单记录,属预期保护 | 等空闲 / 清相关订单后再删 |
