# 东软电动汽车充电桩应用管理平台

一个 Qt/C++ 编写的**充电桩应用管理平台演示项目**,包含三个部分:

- **用户端**:选电站 → 选充电桩 → 充电 → 查看订单/余额(手机风格界面)
- **管理员端**:销售统计、充电桩状态、充电站/桩管理、用户管理(桌面风格界面)
- **数据库中间层**:内嵌 SQLite + TCP 服务,负责存取数据并向两端广播变化

> 这是一个**演示项目**(毕业设计/课设向):充电过程为软件模拟,无真实硬件;服务器与数据库与管理员端同进程。可**同机多进程演示**,也可**多台真实设备联机演示**(见下文「多设备联机教程」)。

## 架构

```
┌────────────┐         ┌──────────────────────────────┐
│  用户端     │  TCP+   │  管理员端(内含服务器+数据库)   │
│ User UI    │  JSON   │   Server + SQLite + Admin UI │
│ RemoteDS◄──┼────────►│   LocalDataSource            │
└────────────┘ 广播通知  └──────────────────────────────┘
```

- 两端界面只依赖抽象接口 `DataSource`(登录、业务操作、受控 CRUD 与 `dataChanged` 信号)
- 用户端用 `RemoteDataSource`(网络),服务器用 `LocalDataSource`(本地 SQLite)——**对界面完全无感**
- 登录身份绑定到当前 TCP 连接:用户只能读取和修改本人资料/订单，管理操作仅管理员可用
- 任何一端写入数据,服务器广播 `dataChanged`,另一端实时刷新
- 表结构集中定义在 `core/TableDef.cpp`,数据要变只改这一处,框架不用动

## 目录结构

```
core/    数据核心层(DataSource 接口 / 本地/网络实现 / 表定义)
server/  数据库中间层(内嵌服务器:收请求、回响应、广播变化)
common/  两端共用(角色选择页 / 全局上下文 / 协议)
user/    用户端(登录、主窗口、6 个页面)
admin/   管理员端(登录、主窗口、5 个页面)
tests/   自检程序(db / net / gui / map / navigation selftest)
resources/  QSS 样式资源
```

## 已实现功能

### 用户端
- 手机号登录(首次输入**自动注册**,昵称 = "用户" + 手机号后四位)
- 电站列表(名称 / 地址 / 下属电桩价格范围 / 每站桩数与空闲桩数)
- 支持腾讯地图全国地点关键词 / 地址候选；选中后覆盖模拟位置，并按该位置距离排序电站
- 电站详情:按类型/功率筛选桩,选桩进入充电
- 电站详情可进入腾讯地图页，支持驾车 / 步行路线、距离和预计时间
- 充电(软件模拟:**1 秒 = 1 分钟**;实时显示时长/电量/费用)
- 结束充电自动结算(时长 × 功率 = 电量,电量 × 单价 = 金额;余额扣款)
- 订单页:历史订单明细,**未完成("充电中")订单可在订单页手动结算**
- 我的:个人信息与余额；充值由用户端发起、服务器校验当前身份后增量入账

### 管理员端
- 登录(默认账号 `admin` / `123456`,首次启动自动创建)
- **销售统计**:已完成订单汇总，可按全部 / 今日 / 近 7 天 / 近 30 天筛选，展示各站营收柱状图和订单占比饼图
- **充电桩状态**:全站电桩实时状态一览(只读),可按状态筛选，并显示充电用户、时长、电量和费用
- **充电桩管理**:增 / 改 / 删充电桩,可按电站筛选
- **充电站管理**:增 / 改 / 删充电站；新增和修改时可搜索地点并自动填写地址、经纬度
- **用户管理**:用户列表(按状态筛选 / 余额 / 注册时间),**封号(冻结) / 解封**,与用户端登录拦截闭环

### 数据层与通信
- SQLite 本地存储(`app.db`,自动建表,首次启动写入演示种子数据:3 个电站、16 根桩)
- TCP + JSON 协议,`dataChanged` 广播:一端写入,所有在线端实时刷新
- 服务器监听 `0.0.0.0:9527`,**同一局域网内多台设备可连同一份数据**(见联机教程)
- 实时刷新机制:通知延迟到事件循环空闲再触发,杜绝"请求套请求"超时
- 服务端权限控制:未登录请求直接拒绝；用户不能读取他人资料/订单、覆盖余额或调用管理接口
- 管理员密码使用随机盐 + PBKDF2-HMAC-SHA256 派生后保存，账号凭据不通过网络查询接口返回
- 服务重启自动恢复进行中订单与电桩占用关系；时长始终由服务器按“1 秒 = 1 分钟”计算
- 充电客户端每秒上报一次心跳，由服务器统一计算并广播实时进度
- 用户端与管理员端分别加载共用 QSS 和角色样式，保持统一的界面风格

### 自检
- `db_selftest`:数据库建表 / 增删改查
- `net_selftest`:登录会话 / 越权拦截 / 跨客户端请求 / 广播同步
- `gui_flow_test`:**9 个用例全部通过**(登录链路 / 充电闭环 / 异常退出恢复 / 管理员页面)
- `map_selftest`:腾讯地址解析 / 关键词候选 API 联调
- `navigation_selftest`:Qt WebEngine 与腾讯 JavaScript API GL 地图初始化

- Desktop gcc 64-bit
- Qt Charts
- Qt WebEngine

再安装编译工具及 WebEngine 运行库：

```bash
sudo apt update
sudo apt install build-essential cmake \
  libnss3 libasound2 libxkbfile1 ca-certificates
```

## 多设备联机教程(两台真实机器)

项目**开箱即支持跨设备联机**,无需改任何代码。下面一步步教你怎么搭起来。

### 原理:谁才是服务器?

- **选「管理员端」的那台设备 = 服务器 + 数据库**。它启动时会自动监听 `0.0.0.0:9527`(即局域网所有网卡),所有数据都存在这台机器的 `app.db` 里。
- **用户端只是一台纯客户端**,它连向"角色选择页里填写的服务器地址"(默认 `127.0.0.1`)。
- 所以联机的本质就是:**让用户端填的地址,从"本机"改成"管理员那台机器的局域网 IP"**。

一句话:**谁跑管理员端,谁就是数据源头;用户端填它的 IP 连过去即可。**

### 前提准备

1. 两台设备在**同一个局域网**(能互相 `ping` 通)。
2. 查出**管理员那台机器**的局域网 IP:
   - Windows:`ipconfig`,看"无线局域网适配器 / 以太网适配器"里的 `IPv4` 地址(形如 `192.168.x.x`)
   - Linux:`ip addr`,看 `inet` 那一行
3. 在**管理员那台机器**上放行 9527 端口(否则用户端连不上):
   - Linux: `sudo ufw allow 9527/tcp`(用 firewalld 就 `sudo firewall-cmd --add-port=9527/tcp`)
   - Windows: 控制面板 → Windows Defender 防火墙 → 允许应用/端口 9527
4. 网络里**只跑一个管理员端**。多开管理员端 = 各自独立的数据库,互不相通。

### 操作步骤

| 步骤 | 管理员那台设备(B) | 用户那台设备(A) |
|---|---|---|
| 1 | 打开程序 → 点「**管理员端**」 | — |
| 2 | 登录 `admin` / `123456` | — |
| 3 | 保持程序运行(它就是服务器) | 打开程序 |
| 4 | — | 角色选择页,把「服务器地址」改成 **B 的 IP**(端口保持 9527) |
| 5 | — | 点「**用户端**」→ 输入手机号登录(自动注册) |
| 6 | 可在「充电桩状态 / 充电桩管理」页查看 | 正常选站、选桩、充电 |

### 联机后你会看到

- A 开始充电 → B 的管理员界面**实时**(约 1 秒内)显示该桩「使用中」,无需手动刷新
- A 结束充电 → B 实时看到该桩回「空闲」、**充电次数 +1、充电时长 +A 显示的分钟数**
- A 的订单 / 余额等一切写入,都落在 B 的 `app.db` 里

### 常见坑与排查

| 现象 | 原因 | 解决 |
|---|---|---|
| A 登录提示"连接服务器失败" | B 的管理员端没开 / 关掉了 | 先启动 B 的管理员端并保持运行 |
| 一直连不上,ping 也通但报错 | 防火墙挡了 9527 | 在 B 放行 9527 端口(见前提准备) |
| 服务器地址填错了 | IP 或端口填错 | 确认 B 的 IP,端口保持 9527 |
| B 提示"启动失败" | 9527 被占用 | 关闭占用端口的进程 |
| A 能看到数据但 B 看不到 A 的操作 | A 连到了别的服务器 | 确认 A 的地址就是 B 的 IP |

### 关键提醒

- **数据永远在管理员那台机器(B)上**。B 关闭管理员界面 → 服务器停止 → A 暂时连不上;数据仍保留在 B 的 `app.db`,B 重新启动即可恢复。
- 想重置数据:在 B 上删除 `app.db` 再启动管理员端(会自动重建种子数据)。
- 如果只是想在一台电脑上体验联机效果,把"管理员机器 / 用户机器"都换成**同一台电脑的两个程序实例**即可(用户端地址保持 `127.0.0.1`)。

## 数据说明

- 数据库文件 `app.db` 生成在**运行时的当前工作目录**(命令行运行就是 `build/` 下)
- 删除 `app.db` 再启动管理员端,即可重置所有数据(用户/订单/桩数据都会清空,默认管理员会重新建)
- 数据库文件已加入 `.gitignore`,**不会进仓库**;新设备克隆项目后运行,得到的是全新的演示数据,与他人本机的数据互不相通

## 常见问题(FAQ)

| 现象 | 原因 | 解决 |
|---|---|---|
| 用户端登录提示"连接服务器失败" | 管理员端还没启动(服务器在管理员端进程里) | 先启动管理员端并保持运行 |
| 管理员端提示"启动失败" | 端口 9527 被占用 | 关闭占用 9527 的进程,或改端口 |
| 报错 "QSQLITE driver not loaded" | 缺 SQLite 驱动包 | `sudo apt install libqt6sql6-sqlite` |
| 程序一闪而过/窗口打不开 | 无图形环境 | 确保有图形界面,或检查 DISPLAY 变量 |
| 手机号登录提示"账号已冻结" | 该用户被管理员端封号 | 管理员端「用户管理」页点「解封」恢复正常 |
| 充电结束后管理员端显示时长固定 +1 | (旧版本缺陷) | 已修复:服务器按订单开始时间计算模拟分钟数 |
| 充电期间管理员端进度不变化 | 用户端未持续运行或网络中断 | 保持用户端充电页和服务端连接正常 |
